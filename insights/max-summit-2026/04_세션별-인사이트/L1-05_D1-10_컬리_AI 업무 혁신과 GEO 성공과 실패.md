## 한 줄 요지
**AI가 우리를 발견하게 만드는 일은 콘텐츠 문제가 아니라 구조 문제다.** 그리고 그 구조를 고친 뒤에도, **"어떤 질문에 우리가 나와야 하는가"는 사람이 정의해야 한다.**

## FACT — 검색 이동은 이미 측정되는 수준
- 최근 6개월 기준, 네이버에서 검색한다는 고객 비중 **−7.2%p**
- 같은 기간 ChatGPT·Gemini 이용 **+8.0%p**
- 연사 해석: "네이버를 넘어섰다는 뜻은 아니지만 **흐름은 이미 바뀌고 있다**"

## CASE ① — 안에서: 급상승 발굴 자동화
**문제 의식** "경쟁사보다 먼저 트렌드를 읽고 상품을 수급하고 싶다." 그런데 **신호가 한 곳에 모여 있지 않다.**

| 단계 | 내용 |
|---|---|
| 소스 4종 | 컬리 급상승 검색어 / 컬리 급상승 판매 상품 / 네이버 검색광고 / 구글 트렌드 |
| 적재 | 전부 BigQuery 테이블로 수집 (소스마다 스키마·컬럼이 달라 정규화 필요) |
| 가공 | Google Apps Script로 가공·정렬 |
| 분석 | Gemini로 분석 → 인사이트 추출 |
| 전달 | Slack 연결, 원하는 주기에 자동 수신 |

**결과** 하루 종일 걸리던 대조·리포트 작업이 자동 수신으로 전환

**핵심은 "검색되는 상품 ≠ 팔리는 상품"의 4분면 해석**
- 검색↑ 판매↓ / 검색↓ 판매↑ / 둘 다↑ 를 교차해 원인을 다르게 진단
- 실사례(샤인머스캣): 검색은 늘었는데 판매는 정체 → 외부 트렌드 확인 → **기후로 당도 편차가 커져 품질 불안** → 대응은 "노출에서 빼기"가 아니라 **당도 높은 물량을 소싱하고 상세·광고·콘텐츠에서 당도를 강조**

> **AI가 못 한 부분** ① 어떤 신호를 봐야 하는지 고르는 일 ② **"급상승의 기준"을 정하는 일** — "어제 10개 팔리다 오늘 11개 팔리면 급상승인가?" 기준을 사람이 넣어야 Gemini가 그 기준대로 구성해 준다

## CASE ② — 안에서: 서비스를 직접 만들다
**멤버스 혜택 계산기**
- 문제: 멤버십 가입자 증가가 정체
- 가설: 월 구독료 대비 실제 할인액을 **금액으로 콕 집어** 보여주면 전환율이 오른다
- 기존 프로세스: 기획 요청 → 우선순위 경쟁 → 임팩트 증명 → 대기
- 실제: **개발 경험 없는 마케터 1명이 Lovable로 2시간 만에 제작, 배포까지 완료**
- 성과 검증(Braze CRM 2개 지점)
  - **앱 내 메시지(탐색 중 노출): 컨트롤 대비 +0.15%p, 유의미**
  - **푸시(이탈 후 알림): 유의미한 증가 없음 → 중단**
  - 해석: 계산기는 **고객의 능동적 입력을 요구**하는 서비스라 구매 맥락 안에서만 작동
- 5월 적용 후 멤버스 정체 구간 돌파 (계산기 단독 성과는 아님을 연사가 명시)

> **"두 시간 만에 만들었다는 게 중요한 게 아니라, 마케터가 가설을 세웠을 때 검증할 수 있는 범위가 넓어졌다는 것이 중요합니다."**

**컬리 AI 스튜디오** (고객 사진 → 캐릭터 이미지 변환)
- 기존 개발 프로세스 45~50일 → **10일 완성**
- 진행 중 트렌드가 터지자 **기획·디자인·개발 리소스 협의 없이 테마를 즉시 추가**
- 성과: 콘텐츠 + 상품 결합 시 PDP 조회·구매 전환 상관이 콘텐츠 단독보다 높음 / 기존 유저 체류시간 **2배 이상** / 30일 내 구매력 있는 고객 **80% 이상** 사용
- **미달**: 신규 고객 확보 목표는 달성 못 함 (연사가 실패로 명시)

## HOW — 밖에서: GEO 3단계 자가진단 (그대로 따라 할 수 있음)
연사의 비유: AI는 **시장을 걸어 다니는 사람**이다. 어떤 가게는 셔터가 내려가 있고, 어떤 가게는 진열대 없이 "주인에게 전화하세요"라고 써 있고, 어떤 가게는 창고처럼 쌓여 있다. **마지막 가게만 정보를 가져간다.**

| # | 진단 | 방법 | 의미 |
|---|---|---|---|
| 1 | **AI 봇 차단 여부** | `도메인/robots.txt` 직접 입력 | 컬리 = `Allow: /` (마이페이지·주문정보만 Disallow) / **아마존 = ChatGPT·GPTBot·Deep Research 전부 차단** — 정책적 선택 |
| 2 | **읽을 수 있는가** | 페이지 소스 보기(`view-source:URL`) | 본문 텍스트가 소스에 남아 있는가. 없으면 AI가 읽지 못함 |
| 3 | **정리되어 있는가** | 소스에서 `ld+json` 검색 | **JSON-LD 구조화 데이터** 유무. 없으면 가격인지 상품명인지 AI가 구분 못 함 |

**컬리 진단 결과** ①②는 통과, **③ JSON-LD 없음** → 사람 눈에는 완벽한 상세페이지(원산지·중량·손질법)가 **AI 눈에는 거의 비어 있었음**

**조치와 결과**
- 상품 페이지에 JSON-LD 적용 (1차 6월 말 / 2차 7월 추가 개선)
- **AI 관련 진단 점수 16점 → 74점**, 이후에도 지속 상승
- 단, **점수가 오른다고 곧바로 AI 답변 노출이 늘지는 않았음** — 시차 존재

**측정 도구 3종**
1. **Kurlex(자체 구축)** — 사내망에서 전 직원이 컬리 상품 페이지 접근 시 그 상품의 **SEO / AEO / GEO 점수와 미비 항목 N건 + 해결 방법**을 표시
2. **Amplitude** — 마케팅 구성 > **AI Visibility** 메뉴로 시간 흐름별 노출 추적
3. 지표: 언급률 / 인용률 / 소스 포함 수 / 소스 포함 비중

## POV — SEO와 GEO의 결정적 차이
> **"SEO는 사람들이 검색하는 검색어를 다 알 수 있잖아요. 그런데 GEO는 사람들이 생성형 AI에 어떤 질문을 하는지를 알 수가 없습니다."**

→ 그래서 **또 사람이 개입해야 한다.** 세상의 모든 질문을 좇는 게 아니라, **"우리 카테고리와 방향성에 맞는 질문 리스트"를 사람이 만들고 그 질문들에서의 순위를 트래킹**하는 것.
- 예: "다이어트 중인데 점심 밀키트 추천해줘", "자취템 수납 보완" 에는 노출되고 싶다
- 예: "집 잘 짓는 방법" 에는 노출될 필요 없다

## POV — 매일 AI를 쓸 때 점검할 3가지
| # | 명제 | 근거 |
|---|---|---|
| 1 | **AI 결과물 ≠ 나의 결과물** | 컬리 채용에 **AI 역량 평가**가 있음. 결과물을 놓고 "왜 그렇게 질문했나 / 왜 2안을 골랐나 / 무엇을 버렸나 / 넥스트 스텝은" 을 묻는데 **대부분 답하지 못한다.** 흡수하지 못했고 자기 생각이 아니기 때문 |
| 2 | **AI가 아는 맥락 ≠ 내가 아는 맥락** | — |
| 3 | **신속 ≠ 신뢰** | ① LLM은 믿을 수 없는 결론을 그럴듯하게 내놓는다 → 검증은 내 몫 ② 신뢰는 사람 사이에서 쌓인다. "빠르고 일 잘하는데 나를 이용하는 사람"과는 일하고 싶지 않다 |

## 멋사 적용 포인트
- **최우선 — GEO 3단계 진단을 이번 주에 그대로 실행.** `likelion.net/robots.txt` → 커리큘럼·모집 상세 페이지 `view-source` → `ld+json` 검색. **비용 0, 반나절.** 브리프 과제 A와 정확히 동일한 절차이며, 컬리가 그 절차의 레퍼런스를 제공한 셈
- **JSON-LD가 없을 가능성이 높음** — KDT 과정 상세는 `Course` 스키마, 모집 공고는 `JobPosting`/`EducationalOccupationalProgram`, FAQ는 `FAQPage` 스키마 적용 후보. 컬리처럼 **점수 baseline → 조치 → 재측정** 순서로
- **"우리가 노출되고 싶은 질문 리스트"를 문서로 확정.** "국비지원 부트캠프 추천", "비전공자 개발자 취업 방법", "AI 부트캠프 어디가 좋아" 등 카테고리별 50~100개. 이게 없으면 GEO 성과 측정 자체가 불가능
- **Kurlex형 내부 대시보드** — 콘텐츠 담당자가 자기 페이지의 SEO/AEO/GEO 점수와 미비 항목을 바로 볼 수 있게. `seo-management/` 허브의 audit 체크리스트를 점수화하면 동일 구조
- **급상승 발굴 자동화는 모집 신호에 그대로 이식 가능** — 내부 지원서 유입 키워드 / 실제 등록 전환 과정 / 네이버 검색광고 / 구글 트렌드 4종을 BigQuery→분석→Slack. **"급상승 기준"을 우리가 먼저 정의**하는 것이 전제
- **"검색되는데 안 팔린다"의 4분면 진단은 모집에 직결** — 문의는 많은데 지원이 없는 과정 = 상세페이지 문제인가, 가격(자부담) 문제인가, 신뢰 문제인가를 분리해서 봐야
- **채용·평가에 "AI 결과물 설명 책임"을 넣는 것**은 즉시 도입 가능. 산출물을 놓고 "왜 이 안인가, 무엇을 버렸는가"를 묻는 것만으로 흡수 여부가 드러남
