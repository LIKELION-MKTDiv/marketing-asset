## 1. 적용 범위 — V2_COURSES allowlist

V2 렌더는 `class_id`가 모듈 상수 `V2_COURSES`(set)에 포함된 과정에만 적용된다. 그 외 과정은
`render_md()` / `render_html()` 하단의 기존 V1 로직을 그대로 탄다.

```python
# generate_future_resume.py
V2_COURSES: set[str] = {"kdt-backendj-27th"}
```

게이트는 각 함수 최상단에서 한 줄로 분기한다 (V1 코드는 손대지 않음, 최소 침습):

```python
def render_html(ext, prof, content, class_id=None):
    if class_id in V2_COURSES:
        return _render_html_v2(ext, prof, content, class_id)
    # ↓ 기존 V1 코드
```

## 2. 7섹션 구조·순서·데이터 매핑

렌더 순서: **상단 → Summary → 보유기술 → 핵심역량 → 프로젝트경험 → 학력(배경) → 교육이수 → 인턴십.**
(프로젝트가 학력보다 앞. 학력=개인 배경이라 프로젝트 뒤.)

| # | 섹션 | 출처 유형 | HTML 함수 | 데이터 출처 |
|---|---|---|---|---|
| 상단 | 이름·headline·contact·부트캠프뱃지 | 개인 | `_render_html_v2()` 조립부 | `ext.personal_info`, `content.headline`, `ext.bootcamp_info` |
| 1 | Summary | 개인 | 조립부 | `content.career_objective` |
| 2 | 보유 기술 | **고정+개인** | `_v2_render_skills()` → `_v2_skill_render_groups()` | 하드스킬 그룹=**고정블록** `V2_FIXED_SKILLS_BY_COURSE`(전원 동일) + Soft Skills=`prof.soft_skills`(개인, 상위 3) |
| 3 | 핵심 역량 및 활동 | 개인 | `_v2_md_to_html(secs["핵심 역량 및 활동"])` | `content.sections["핵심 역량 및 활동"]` |
| 4 | 프로젝트 경험 | **고정** | `_v2_render_projects()` → `_v2_parse_projects()` | **고정블록** `templates/bootcamp_common/{class_id}.md`의 `## 프로젝트 경험`(전원 동일) |
| 5 | 학력(배경) | 개인 | `_v2_background_sections()` | 고정 3섹션(기술스택·프로젝트포트폴리오·핵심역량) 제외한 **개인 배경 섹션**을 원본 제목 그대로. 학생=학력 / 전향자=커리어전환·실무경력 등. 배경 데이터 없으면 **생략**(환각 금지) |
| 6 | 교육 이수 내역 | 고정+커스터마이즈 | `_v2_render_edu()` | 공통블록 "부트캠프 교육 이수 내역" + `V2_CURRICULUM_TAGS_BY_COURSE`/`V2_INTRO_BY_COURSE`/`V2_PERIOD_LABEL_BY_COURSE` |
| 7 | 인턴십 | 고정 | `_v2_md_to_html(intern_md)` | 공통블록 "인턴십" |

MD V2(`_render_md_v2()`)는 위와 동일한 7섹션·순서·데이터 출처를 마크다운으로 미러링한다(헤더
`#`/섹션 `##`, 보유기술은 그룹별 `###` 소제목 + 콤마 나열, 프로젝트는 카드 대신 불릿). HTML·MD가
프로젝트·스킬·배경 렌더 헬퍼(`_v2_parse_projects`·`_v2_skill_render_groups`·`_v2_background_sections`)를
공유하므로 두 포맷의 내용은 항상 일치한다.

**왜 프로젝트·하드스킬이 고정블록인가 (2026-08-07 개정):** 원래는 지원자별 LLM 섹션을 파싱했으나
포맷이 사람마다 제각각이라 truncation·마크다운 노출 버그가 반복됐다(§9 이력). backendj-27th의
1~3차 프로젝트와 기술 스택은 부트캠프 표준이라 전원 동일 → 파싱을 폐기하고 고정블록으로 통일.
학력만 개인 배경이라 지원자 데이터에서 뽑되, 데이터가 없으면(자소서 미기재 전향자) 생략한다.

푸터 문구(`본 이력서는 {과정명} 수료 후 예상 역량을...`)는 V1과 동일하게 `_footer_bootcamp_name()`
(과정 공용 함수)을 그대로 재사용한다 — 과정명 정규화 로직을 이중 관리하지 않기 위함.

## 5. 과정별 커스터마이즈 지점 (신규 과정마다 달라질 수 있는 자리)

과정마다 값이 달라질 수 있는 4개 지점을 `generate_future_resume.py`에 `# [과정별 커스터마이즈
지점 N]` 주석과 함께 dict 상수로 뺐다. 명시 등록이 없는 과정은 각각 제네릭 fallback으로
동작해 "코드 수정 없이도" 최소한의 형태로 렌더된다.

| # | 무엇 | 등록 dict | 미등록 시 fallback |
|---|---|---|---|
| 1 | 보유기술 3그룹 정의 (예: 그로스마케팅엔 DevOps 카테고리가 없음) | `V2_SKILL_GROUPS_BY_COURSE` | `_v2_skill_groups_for()` — 기술스택 원본 카테고리를 등장 순서대로 각자 그룹화 (`Tools`/`보유역량` 제외) |
| 2 | 교육이수 커리큘럼 태그 큐레이션 | `V2_CURRICULUM_TAGS_BY_COURSE` | `_v2_derive_curriculum_tags()` — 공통블록 표의 마지막 열("핵심 역량")에서 동적 추출(상위 7개) |
| 3 | 부트캠프 소개 2줄 문구 | `V2_INTRO_BY_COURSE` | `_v2_intro_text()` — `bootcamp_info.track`/`bootcamp_name` 기반 제네릭 한 문장(사실 창작 없음) |
| 4 | 교육 기간 라벨("N개월 (H시간)") | `V2_PERIOD_LABEL_BY_COURSE` | `_v2_format_period()` — 공통블록 원문의 날짜 2개 + "총 N시간" 표기에서 개월수를 올림 계산 |
| 5 | **보유기술 하드스킬 고정블록** (Backend/Frontend/DevOps 표준 태그, 전원 동일) | `V2_FIXED_SKILLS_BY_COURSE` | `_v2_parse_tech_stack()` — 지원자별 기술스택 파싱(6+포맷 관용 처리, 취약). **미등록 과정은 파싱, 등록 과정은 고정블록.** |

**참고:** fallback은 "새 과정을 코드 수정 없이도 깨지지 않게" 하는 안전망이지, 큐레이션 품질을
보장하지 않는다. 실제 발송 전에는 아래 온보딩 체크리스트 ④(샘플 렌더 확인)에서 반드시
눈으로 확인하고, 필요하면 위 dict에 항목을 추가해 큐레이션한다.

## 8. 생성 / 수정(재생성) 운영 가이드

### 8-1. 신규 생성 (풀 파이프라인)

특정 날짜 지원완료자를 처음 생성할 때. Phase 1~4(추출→분류→콘텐츠→렌더) 전체를 돌리고
초안까지 만든다. **LLM(claude CLI, 구독 토큰)을 호출**한다.

```bash
cd resume-pipeline
python3 daily_runner.py --target-date YYYY-MM-DD --dry-run --ignore-business-day   # ① 대상 확인
python3 daily_runner.py --target-date YYYY-MM-DD --draft  --ignore-business-day --parallel 3   # ② 생성+초안
```

- 필터는 `지원상태=지원완료` 하나(CLAUDE.md). 합불·자소서 유무로 거르지 않는다.
- 초안은 `drafts.create`만(임시보관함). **발송은 Hoya가 직접** — 마루/에이전트 발송 권한 없음.
- 수신자는 지원서 이메일(K열) 1순위, 가입 이메일 폴백(daily_runner가 처리).

### 8-2. 수정(재생성) — 렌더러만 바꿨을 때: intermediate에서 재렌더 (LLM 재실행 없음)

렌더 로직(V2 버그 수정·포맷 변경)만 고쳤고 **콘텐츠(intermediate)는 멀쩡할 때.** 이미 만들어진
`_1_extracted/_2_profile/_3_content.json`을 그대로 읽어 고친 `render_html()`/`render_md()`로
다시 렌더 → Drive 파일 덮어쓰기 → 초안 재생성. **빠르고 결정적, LLM 안 씀, 좋은 콘텐츠 보존.**

```python
import json; import generate_future_resume as g
from pathlib import Path
from mail_dispatch.gmail_draft import create_draft_for_applicant
OUT = Path(".../resume_pipeline/kdt-backendj-27th/YYYY-MM-DD")           # Drive 출력 폴더
INT = Path(".../resume_pipeline/_logs/kdt-backendj-27th/YYYY-MM-DD/intermediate")
for name, email in {"홍길동": "a@b.com"}.items():
    ext  = json.load(open(INT / f"{name}_1_extracted.json", encoding="utf-8"))
    prof = json.load(open(INT / f"{name}_2_profile.json",   encoding="utf-8"))
    cont = json.load(open(INT / f"{name}_3_content.json",   encoding="utf-8"))
    (OUT / f"{name}_미래이력서.html").write_text(g.render_html(ext, prof, cont, class_id="kdt-backendj-27th"), encoding="utf-8")
    (OUT / f"{name}_미래이력서.md").write_text(g.render_md(ext, prof, cont, class_id="kdt-backendj-27th"), encoding="utf-8")
    create_draft_for_applicant(recipient=email, name=name, output_dir=OUT)   # HTML+MD 둘 다 있어야 성공
```

- 수신자 이메일은 이전 생성 로그의 `수신자` 라인(K열 우선 적용된 값)을 재사용한다.
- **재렌더 후 반드시 스크린샷 QA**(§6-④): 렌더 버그 수정은 화면으로 확인. grep만으로 완료 금지.

### 8-3. 수정 — 콘텐츠 자체가 깨졌을 때(Phase 3 실패): 풀 재생성

`_3_content.json`이 아예 없거나(Phase 3 미완료) MD/HTML 한쪽만 만들어진 케이스. intermediate가
불완전하므로 8-2로는 못 고친다. **출력 파일을 지워 "미생성"으로 인식시킨 뒤 8-1 풀 재생성**한다.

```bash
rm -f ".../kdt-backendj-27th/YYYY-MM-DD/{이름}_미래이력서.html"   # 부분 산출물 제거(우리 산출물이라 삭제 OK)
python3 daily_runner.py --target-date YYYY-MM-DD --draft --ignore-business-day   # 미생성분만 재생성(나머지 스킵)
```

### 8-4. 초안 정리 — create-only, 삭제는 Hoya

`gmail_draft`는 `drafts.create`만 있고 **update/삭제가 없다.** 재렌더로 초안을 다시 만들면
수신자별로 초안이 누적된다(구버전 + 신버전). 마루/에이전트는 메일·메시지를 삭제할 수 없으므로,
**Hoya가 임시보관함에서 수신자별 가장 최근 1건만 남기고 삭제**한다. 재생성 완료 보고에 정리
대상(수신자 목록 + 인당 건수)을 함께 준다.

## 9. 버그 수정 이력 — 포맷 취약성과 고정블록 전환 (2026-08-06~07)

8/4~8/6 backendj-27th 재생성에서 발견·수정. 공통 뿌리는 **"LLM 출력 포맷이 지원자마다 다르다 →
고정 슬롯을 정규식으로 파싱하면 계속 깨진다."**

| 버그 | 증상 | 원인 | 해결 |
|---|---|---|---|
| 프로젝트 truncation | 원본 1000자+ → 18~113자로 짤림 | `\n---\n` 구분 의존·`**개요:**` 콜론위치·`—` 제목구분자 파싱 실패 | **고정 공통블록**(`## 프로젝트 경험`) — 파싱 폐기 |
