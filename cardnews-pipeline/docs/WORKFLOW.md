# 제작 흐름과 실전 팁

## 1. 한 편을 만드는 순서

| 단계 | 할 일 | 산출물 |
|---|---|---|
| 1 기획 | 장별 역할을 먼저 정한다: 커버(후킹) → 문제·반전 → 근거(데이터) → 해석·주의 → 브랜드 메시지 → 엔드컷(행동 지시) | 장별 카피표 |
| 2 배경 | 사진을 고르거나 생성 AI로 배경 플레이트를 만든다 (아래 프롬프트 함정 참고) | `assets/` |
| 3 spec | 카피를 `html`에, 배경을 `bg`에 넣는다 | `spec.json` |
| 4 렌더·검수 | `python -m cardnews.render ...` 실행, 검수 이슈 0건까지 고친다 | PNG, `audit.json` |
| 5 눈 검수 | 휴대폰 화면 크기로 보고, 피드 썸네일(축소)에서 커버 제목이 읽히는지 확인 | |
| 6 발행 | 통과한 PNG를 업로드. 캔바에서 마감하는 브랜드는 PNG를 시안으로 쓰고 같은 좌표·크기로 옮긴다 | |

## 2. 검수에서 자주 걸리는 것

| 증상 | 원인 | 고치는 법 |
|---|---|---|
| 여백침범 | 한 줄이 너무 김 | 줄을 나눈다. 그래도 넘치면 카피를 줄인다. 글자 크기는 내리지 않는다 |
| 명암비 미달 (사진 배경) | 글자 영역 일부가 밝음 | 글자를 `<div class='scrim'>`으로 감싸거나 `bg.mode`를 `full`/`blur`로 |
| 명암비 미달 (브랜드 색 글자) | 중간 밝기 색은 대비 상한이 낮음 | 브랜드 가이드의 색별 목표를 `audit.contrast`에 넣고, 그래도 미달이면 흰 글자로 |
| 명암비 미달 (흰 버튼 위 색 글자) | 밝은 색끼리 | 버튼 글자를 진한 색으로 (`color:var(--c-secondary)`) |
| 글자크기 하한 | 캡션·출처가 너무 작음 | 하한 이상으로 키우거나 출처를 한 줄로 줄인다 |

## 3. 엔드컷은 매체별로

| 매체 | 목적 | 엔드컷 카피 방향 |
|---|---|---|
| 인스타그램 | 도달 확장 | 공유·저장 유도 ("친구에게 공유해 보세요", "저장해두고 다시 보기") |
| 유튜브 | 검색 전환 | 검색 유도 ("지금 검색하고 확인해보세요" + 검색어). 저장 유도는 넣지 않음 |

카드뉴스에는 누를 수 있는 링크가 없으므로 엔드컷 카피가 유일한 전환 장치입니다. 유튜브용은 16:9(1920×1080) 또는 9:16 캔버스로 `canvas`를 바꾼 브랜드 키트를 따로 둡니다.

## 4. 배경 플레이트 생성 프롬프트 함정

| 함정 | 증상 | 대응 |
|---|---|---|
| "글자 자리를 비워 두라(clear rectangular area)" | 모델이 빈 사각형을 그려 넣음 | 여백을 도형 명사로 쓰지 말고 "그 구역에서 무엇이 계속되는지"로 서술 |
| "조용한 영역(quiet band)"만 지정 | 물체는 빠져도 밝기가 들쭉날쭉 | "low and even in brightness"까지 명시하고 적용 범위(좌우 가장자리 등)를 적음 |
| 비율을 프롬프트로 지정 | 무시됨 | 생성 도구의 비율 선택을 4:5로 먼저 설정 |

## 5. 역할 분담 권장

| 역할 | 담당 |
|---|---|
| 브랜드 키트 유지 (`brands/브랜드/`) | 브랜드 담당자 1명. 가이드가 바뀌면 `brand.json`과 `DESIGN_GUIDE.md`를 함께 고침 |
| 콘텐츠 spec 작성·렌더 | 콘텐츠 담당자 |
| 엔진 수정 (`cardnews/`) | 변경은 Pull Request로. 다른 브랜드 결과가 바뀌지 않는지 두 샘플을 다시 렌더해 비교 |
